# homological — pedagogical audit (2026-05)

**Section:** Algebra & homological
**Compared against:** category-theory, derived-categories

## Summary
A strong, deeply-instrumented page: 16 numbered sections, 12 interactive widgets, every section §1–§15 carries a `<div class="quiz">`. The most load-bearing issue is **two-tier notation drift** introduced when §12–§14 were back-filled — `\mathrm{Ext}/\mathrm{Tor}/\mathrm{Hom}/\mathrm{Tot}` for the same operators that §1–§9 spell `\operatorname{Ext}/\operatorname{Tor}/\Hom`, and `\mathbb{R}^n F` for what §9 calls `R^iF`. After that, four late sections lack widgets (§5, §12, §13, §14).

## Findings

### Notation drift
- **Same page splits `\operatorname{Ext}` vs `\mathrm{Ext}` for the same object.** §2 line 644 writes `$\operatorname{Ext}^1(\mathbb{Z}/n,\mathbb{Z})$`; §9 line 2126 `$\operatorname{Ext}^i_A(M,N)$`; but §12 line 2741 writes `$\mathrm{Ext}^*_R(A,B)$`, §13 line 2771 `$\mathrm{Ext}^n_R(M,N)$`, and §15 line 2823 swings back to `$\operatorname{Ext}^i_\mathcal{A}(M,N)$`. **High priority — semantic operator with two spellings on one page.** `derived-categories.html` exhibits the same split (line 459 `\mathrm{Ext}_R^i` vs §1 `\Hom`), so the canonical resolution is "promote `\mathrm{Ext}` everywhere → `\operatorname{Ext}`" (which the macros block could absorb as `\\Ext`).
- **`\mathrm{Tor}` vs `\operatorname{Tor}`.** §8 line 2022 `$\operatorname{Tor}_1^R$`; §9 line 2127 `$\operatorname{Tor}_i^A$`; but §12 line 2740 `$\mathrm{Tor}^R_*$`, §13 lines 2754/2757/2763/2767 all `$\mathrm{Tor}^R_n$`. Same split, same fix. `derived-categories.html` line 623 also uses `\mathrm{Tor}_i^R` — corpus-wide drift, not just local.
- **`\mathrm{Hom}` re-asserted where the macro `\Hom` is in scope.** The macros block defines `\\Hom = \\operatorname{Hom}` (line 25), and §1–§9 use `\Hom` consistently (e.g. lines 644, 1650, 2126). §12 line 2741 and §13 line 2771 hand-write `\mathrm{Hom}(P_\bullet, I_\bullet)` instead. Cosmetic, easy fix — `\Hom` is already loaded.
- **`\mathrm{Tot}` vs `\operatorname{Tot}` and `\mathrm{Ch}` vs `\operatorname{Ch}` inside the same §.** §15 line 2816 writes `$\operatorname{Ch}(\mathcal{A})$` and line 2820 `$\operatorname{Ch}(\mathcal{A})$`, but the §15 widget option (line 2833) renders `$\mathrm{Ch}(\mathsf{Ab})$`. Similarly §12 lines 2725/2727/2731 use `\mathrm{Tot}`. Medium priority — same operator, same paragraph, two spellings.
- **`\mathbb{R}^n F` vs `R^iF` for the derived functor.** §9 line 2120 introduces "$R^iF$ or $L_iF$"; §14 lines 2796–2797 escalate to `$\mathbb{R}^n F(C^\bullet)$` and `$\mathbb{R}^p G \circ \mathbb{R}^q F \Rightarrow \mathbb{R}^{p+q}(GF)$` *without* flagging that the blackboard-bold $\mathbb{R}$ is the hyper-derived variant. `derived-categories.html` §5 line 614 uses plain `RF` for the total derived functor. **High priority** — different glyphs, same word, no callout. Either keep $\mathbb{R}$ for hyper- and add a half-sentence ("we use $\mathbb{R}$ for the hyper-derived variant to distinguish it from the object-level $R^iF$ of §9") or normalize.
- **`\partial` vs `\delta` for the connecting map.** §3 line 803 introduces `$\delta:\ker\gamma\to\operatorname{coker}\alpha$`; §5 line 1647 then writes `$\partial : H_n(C) \to H_{n-1}(A)$` for the "same" connecting map of the long exact sequence. Both spellings are textbook-standard, but a one-line aside ("$\partial$ is the snake-lemma $\delta$, applied degree-by-degree") would close the loop.

### Undefined jargon
- **"abelian category" used in §4 long before §15 defines it.** §4 line 1500 says "or objects of any abelian category" with no callback; the formal definition arrives at §15 line 2807. Same term reappears defined-only-by-context in §10 line 2416 ("In a category with enough projectives") and §12 line 2719. Fix: a one-clause forward pointer at §4 ("we'll define this precisely in §15").
- **"$F$-acyclic"** at §14 line 2797 ("comes from applying $G$ to a Cartan–Eilenberg resolution of $F$-acyclics") — first and only use, no definition. Standard graduate term but appears mid-sentence inside the Grothendieck-spectral-sequence bullet; one parenthetical ("an object $X$ with $R^iF(X)=0$ for $i>0$") would close it.
- **"hyper-derived functor"** at §14 line 2796 — defined inline ("computed as $H^n(F(P^{\bullet,\bullet}))$") but the term itself is never glossed before the colon. Quick fix: bold-link "hyper-derived" to a one-sentence definition.
- **"quasi-isomorphism" used in §14 before §15 introduces it casually**, and §15's "invert all quasi-isomorphisms" assumes the reader recognizes the term. It does have a callback to derived-categories.html§2, which is the right move — but only via the §15 outro. §14 line 2782 ("a double complex $P^{\bullet,\bullet}$ together with a quasi-isomorphism $P^{\bullet,\bullet} \to C^\bullet$") is the first occurrence and could use a half-sentence aside.
- **"Yoneda Ext"** at line 619 (in derived-categories.html — irrelevant) and §16 line 2970 of homological mentions "Long exact sequences become *distinguished triangles*" without ever explaining what a distinguished triangle is on this page (it links to §15's classifier widget, which says "distinguished triangles replace short exact sequences" — definitional gestures, not a definition). Acceptable because §16 is explicitly a "where this goes next" outro, but worth a "see derived-categories.html#triangulated-structure" callback (currently the callback under §15 covers it via the related-asides).

### Tone mismatches
- **§12, §13, §14, §16 read drier than §1–§11.** The earlier sections regularly drop the conversational tells of the house style — "Everyone meets the snake lemma once and then uses it forever" (§3 line 794), "The point is that $\delta$ exists at all" (§3 line 823), "Trace out the tree of implications — it looks like the whale on a Moby-Dick cover" (§4 line 1511), "Two stars" (§9 line 2124), "The strange thing about homological algebra…" (outro 2976). §12 line 2745 ("Double complexes are the technical universal donor") gestures at the voice but the surrounding §§12–14 are otherwise textbook-like enumeration of definitions / properties / two big uses. The contrast is the same shape `commutative-algebra.html` exhibits in its §9/§14/§16 ("appended later, not revoiced"). Medium priority.
- **§15 widget hint over-claims.** Line 2828 reads `<div class="hint">pick a category, see which axioms hold</div>` — but the widget is a static lookup of pre-baked "is it abelian?/triangulated?" verdicts, not an axiom-by-axiom checker. Soften to "look up axiom verdicts for canonical examples" or wire in real axiom evaluation.

### Missing worked examples
- **§5 (long exact sequence in homology) has no widget.** It's the central "tool you reach for first" sentence and arguably the most-used result in the subject, but the section consists of two paragraphs and a callback. A widget that animates the snake-lemma → LES iteration (cribbing from the §3 snake widget at lines 836–841) would close the gap.
- **§12 (double complexes) has no widget**, despite the §11 spectral-sequence widget already drawing a 2×2 double complex grid. A "totalize this 2×2" toy that lets you flip the sign convention and watch $d^2 = 0$ pass/fail would be high-value.
- **§13 (Tor symmetry) has no widget.** The proof-via-double-complex spectral sequences would benefit from a side-by-side widget showing the two collapse patterns ($H^v$ first vs $H^h$ first) on a small example. Right now it's pure exposition.
- **§14 (Cartan–Eilenberg) has no widget.** A "step-through a CE resolution of a 2-term complex" stepper would parallel the §3 snake-lemma stepper. Hardest of the three to author, but would land §14 squarely in the "every concept has a poke-able toy" rule.
- §15 has the abelian/triangulated classifier, which is a static lookup table dressed as a widget — it answers a single binary, not "poke and watch." Cf. category-theory.html §15 (`#twocat`) which the peer audit also flagged for the same kind of pre-baked-mode behavior.

### KaTeX macros / formatting
- **No undeclared local macros.** Helper macros are exactly the canonical six (`\Spec`, `\Gal`, `\Hom`, `\tr`, `\ad`, `\ind`) — same block as `category-theory.html` and `derived-categories.html`. No invented delimiters; `$…$`, `$$…$$`, `\(…\)`, `\[…\]` only.
- **Page-global helper block omits `ensureArrow` / `drawArrow` / `drawNode`** (the canonical 2D helpers from category-theory.html). Instead, lines 186–358 carry a topic-specific block (`Q`, `Qadd`, `matRank`, `smithNormalForm`, `zmoduleFromSmith`) consumed by the §1, §10 widgets. Each widget that needs an arrow re-implements its own marker `<defs>` and arrow-drawing function inline (e.g. lines 1399–1426 in §3, 1586–1611 in §4, 1801–1828 in §6). **Cosmetic, but contradicts AGENTS.md** "**Copy verbatim** from category-theory.html — do not rewrite." Either add the canonical helpers and refactor (large) or note the deviation in the helper block comment (small). Note the snake-shape widget at §3 (lines 854–1333) is the schema-driven `widget-diagram-editor.js`, which has its own helpers — not the issue.
- **Widget chrome is fully canonical.** Every widget uses `.widget / .hd / .ttl / .hint / .row / .readout / .small / .note / .ok / .bad`. No ad-hoc classes detected.
- **Cosmetic ASCII-in-readouts pattern.** The §1, §3, §6, §8, §9, §10, §11, §15 widget readouts emit raw "ℤ", "ℚ", "Z/2", "Tor_1", "ker ∂_1" as plain text inside `<div class="readout">` rather than KaTeX-rendered (e.g. line 598 `H_0 = ker ∂_0 / im ∂_1 = ${dim0} − ${rank_d1} = ${H0}  →  Q^${H0}`). This is consistent across the page and matches monospace readouts elsewhere in the corpus, so probably intentional — but the prose immediately above the same widgets uses KaTeX `\mathbb{Z}`, so the eye toggles between two glyphs for the same object. Low priority; mention only.
