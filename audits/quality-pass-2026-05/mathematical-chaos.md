# mathematical-chaos — pedagogical audit (2026-05)

**Section:** Analysis
**Compared against:** dynamical-systems, complex-analysis

## Summary
Compact, dense page (7 numbered sections + Connections, 9 widgets — strong: a registry-backed `inline-code-cell`, a registry-backed `recurrence-plotter`, a registry-backed `proof-scrubber` for Sharkovsky's order, plus six bespoke SVG interactives). Voice and notation match the two peers cleanly; helper block, macro list, and widget chrome are byte-equivalent to `category-theory.html`. The only real findings are pedagogical density tradeoffs at the heads of §3, §5, and §6 — chains of named theorems / measures land before any inline gloss — plus a couple of in-SVG `mathrm`-vs-Unicode glyph slips inside the `proof-scrubber` steps (KaTeX is not invoked inside `svgInner`).

## Findings

### Notation drift
- `\mathbb{R}^n`, `\mathbb{Z}`, `\mathbb{N}` (lines 268, 269, 543, 662, 682, 848) match `dynamical-systems.html` (lines 332, 333, 1469, 1540) and `complex-analysis.html` (lines 303, 308, 309) exactly. No `\R/\Z/\C` shortcut macros — clean.
- `\colon` for typed-function colons (`f\colon\mathbb{R}^n\to\mathbb{R}^n` at line 268, `T\colon X\to X` at line 750, `\sigma\colon X\to\{0,\ldots,k-1\}^{\mathbb{Z}}` at line 662) used consistently. Matches both peers.
- `\mathrm{top}`, `\mathrm{Fix}`, `\mathrm{SRB}` for fixed-decoration subscripts (lines 665, 666, 754, 756) — consistent with the corpus convention (`\mathrm` for non-argument-taking semantic decorations, `\operatorname` for operators with arguments, e.g. dynamical-systems' `\operatorname{div}` at line 676). Clean.
- `\triangleright` (line 945) for the Sharkovsky order is a fine choice but worth noting it appears nowhere else in the corpus — a one-line gloss like "(read $a\triangleright b$ as 'period $a$ forces period $b$')" would help readers who only see it once. Cosmetic.
- One in-SVG inconsistency inside the `proof-scrubber` `svgInner` strings (which KaTeX does **not** re-render): line 564 uses Unicode `Λ`, `∩_{n∈ℤ}`, `fⁿ`, `≅`, `{0,1}^ℤ` while line 543's prose uses `\Lambda`, `\bigcap_{|n|\le k}`, `\{0,1\}^{\mathbb{Z}}`, `\cong`. Same set, two notations one paragraph apart. Same pattern in lines 560, 562, 563, 564 (Unicode `μ`, `λ`, `²`, `³`, `→`, `∞`, `ⁿ`). Cosmetic — the SVG strings can't carry KaTeX, but using ASCII transliterations like `Lambda`, `subset`, `f^n`, `iso` (matching e.g. `complex-analysis.html`'s SVG conventions) would feel less like "two different scripts in one widget".

### Undefined jargon
- **§1 line 268: "(i) sensitive dependence on initial conditions, (ii) topological transitivity, and (iii) dense periodic orbits — Devaney's triple."** The three components are listed but never expanded inline. The §1 callback aside does point to `dynamical-systems.html#chaos`, which fully unpacks them at line 1235–1237 — so the reader has a path — but a single inline parenthetical for "topological transitivity" (e.g. "every pair of opens eventually overlaps") would let §1 stand alone. Low-priority because the callback exists.
- **§3 line 452 "two symmetric saddle-foci $C_\pm$"** — first appearance of "saddle-focus" on the page; no inline gloss. `dynamical-systems.html`'s phase-portraits §3 covers saddle/focus/spiral types but the §3 callback here points to `dynamical-systems.html#attractors`, not `#phase-portraits-2d` or `#fixed-points-and-linearization`. A pointer to the linearization section (or one inline phrase like "complex-eigenvalue saddles") would close the gap.
- **§3 line 543 "uniformly hyperbolic chaotic system"** — "uniformly hyperbolic" lands once, undefined, in the closing summary line of stage 4 and never returns. `dynamical-systems.html` doesn't define it either. Either inline-gloss ("uniform expansion / contraction in transverse directions") or drop the qualifier.
- **§4 line 662: "Markov partition"** is parenthesized as a synonym for "invariant partition" but the term is technically stronger (it requires the cell-images to respect partition boundaries). Cosmetic — inline gloss would help — but most readers will skim past.
- **§5 line 754** introduces SRB measures via a single sentence ("the unique $f$-invariant measure $\mu_{\mathrm{SRB}}$ supported on the attractor whose conditional measures along unstable manifolds are absolutely continuous with respect to the unstable Lebesgue"). "Conditional measures along unstable manifolds" is a four-deep nesting (conditional measure / disintegration / unstable manifold / Lebesgue restriction) and lands on a reader who has seen none of them defined in this page. Pesin's formula in §4 line 668 already mentions SRB by forward-reference; §5 then doesn't pause to unfold. **High-priority pedagogical**: a 2–3 sentence interlude unpacking "what does it mean to disintegrate a measure along the unstable foliation?" would make §5 self-contained.
- **§6 line 845: "completely integrable Hamiltonian on $T^*Q$ has $n$ Poisson-commuting first integrals; Liouville–Arnold says regular compact level sets are tori $T^n$..."** This sentence carries six unfamiliar terms (cotangent bundle, integrable, Poisson-commuting, first integral, Liouville–Arnold, regular level set) before any are defined; the §6 callback points to `hamiltonians-classical-mechanics.html#integrable` which is good, but the prose still loads pre-callback. Suggest one sentence of inline scaffolding: "An integrable Hamiltonian is one where as many independent conserved quantities as there are degrees of freedom Poisson-commute (so they all flow simultaneously); Liouville–Arnold then says..."
- **§6 line 849: "smoothly deformed Lagrangian tori"** — "Lagrangian" lands undefined. Same callback covers it but again the prose precedes the callback. Low-priority.
- **§6 line 851: "Poincaré–Birkhoff theorem"**, **"homoclinic tangle"**, **"Arnold-style diffusion"** — three named results in one paragraph, each assumed familiar. Homoclinic tangle has a callback to `three-body-problem.html#poincare`, good. Poincaré–Birkhoff and Arnold diffusion don't. Low-priority.
- **§Connections line 1002: "GOE/GUE"** is acronym-only; "Gaussian Orthogonal/Unitary Ensemble" expansion would help even though the very next clause says "random matrix universality" and the bullet at line 1009 spells GOE/GUE again. Cosmetic.

### Tone mismatches
- Voice is closer to `dynamical-systems.html`'s register (terse-but-warm, occasional theorem boxes, history-flavored asides like "Mitchell Feigenbaum did this numerically before the rigorous proofs (Lanford 1982 for the quadratic case, computer-assisted) arrived" at line 326) than to `complex-analysis.html`'s more conversational Needham flavor. Second-person voice is used twice (lines 308 "Drag the slider", 332-class hints) vs 7 times in complex-analysis and 14 times in category-theory. **Cosmetic — the page would feel one notch warmer with one or two more "you" / "watch" prompts in §4 and §5 prose** (currently those sections are pure third-person exposition before the widget; §5 line 750–756 is four straight paragraphs of definition before the histogram-convergence widget gives the reader something to do).
- §5 lines 754–756 (SRB measure introduction) are the page's longest formula-with-narration wall — three consecutive paragraphs of dense theory with no widget interruption. The widget arrives at line 758 and is excellent (Birkhoff-CLT histogram convergence) but the lead-up is the section that most violates "every concept has a toy you can poke" pacing in spirit. The information is correct and well-organized; it's just unbroken. **Low-priority.**
- §3 line 543 (the horseshoe paragraph) is similarly dense — four sentences cramming the construction, the Cantor-set conclusion, the conjugacy to the shift, periodic-orbits-of-every-period — before the `Smale's horseshoe` step-through widget rescues the reader. Same shape as §5; the widget more than redeems it. The §3 narration could split into two paragraphs around "The points that stay inside…" to give the eye a break.

### KaTeX macros / formatting
- Macro block (lines 22–28) is byte-identical to `dynamical-systems.html:38–45` and `complex-analysis.html:38–45` and `category-theory.html`'s macro list. No locally redefined macros, no shortcuts (`\Z`, `\R`, `\C` not introduced). Clean.
- Helper-block (lines 189–241) is essentially byte-identical to `category-theory.html`'s 2D helper (the diff is a single trailing blank line). The page does not import any 3D helpers; correct, since the Lorenz widget is a 2D (x,z) projection rather than a draggable 3D mesh.
- Widget chrome is uniform: every `<div class="widget">` carries `<div class="hd"><div class="ttl">...</div><div class="hint">...</div></div>`, and every interactive uses `.row`, `.readout`, `.small` consistently. No ad-hoc classes. (Quick spot-check: lines 328–337 bifurcation, 454–465 Lorenz, 545–555 horseshoe, 670–683 symbolic, 758–769 ergodic, 853–864 standard-map — all match the canonical chrome.)
- All seven numbered sections carry a `<div class="quiz" data-concept="mchaos-...">` placeholder; concept ids follow the `mchaos-*` prefix convention (lines 301, 445, 657, 745, 840, 939, 996). Anchor contract enforced by `smoke-test.mjs` — assume intact.
- Page-bottom `MVQuiz.init('mathematical-chaos')` IIFE present at lines 1016–1022. Loaders for `widget-recurrence-plotter`, `widget-inline-code-cell`, `widget-proof-scrubber` correctly listed in `<head>` (lines 179–181).
- KaTeX delimiters: page mixes inline `$…$` for displays-via-`<p style="text-align:center">` (e.g. lines 269, 323, 451, 665, 848, 945) instead of `$$…$$`. Both peers do the same; this is the corpus default for "centered display I want to keep inside a paragraph stylistically". No drift.
- One markup nit (low-priority): the Sharkovsky `proof-scrubber` step at line 981 contains `f\\colon I\\to I` inside an `svgInner` body — but `svgInner` strings are injected into the SVG directly and KaTeX does not run inside `<svg>` (the `renderMathInElement` walks DOM but skips SVG). So the literal string `$f\\colon I\\to I$` will appear unrendered when the user scrubs to step 5. Same issue in the `body` / `text` strings of every step — but those go through the proof-scrubber's text rendering which (assuming it runs KaTeX on the body before mounting; check `widgets/proof-scrubber/index.mjs`) may handle it. Worth a one-line check that the scrubber re-runs KaTeX after each step transition.
