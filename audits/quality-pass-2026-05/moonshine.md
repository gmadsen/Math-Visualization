# moonshine — pedagogical audit (2026-05)

**Section:** Modular forms & L-functions
**Compared against:** vertex-operator-algebras, modular-forms

## Summary
A strong, well-paced page that mostly hews to house style and integrates cleanly with its two peers (notation for `\mathbb{M}`, `\mathrm{SL}_2(\mathbb{Z})`, `\mathcal{H}`, and `V^{\natural}` all match). The main pedagogical issues are several jargon-before-definition slips in §5–§7 (VOA, generalized Kac–Moody, Hall divisor, supersingular, replicable, Faber polynomials all appear in prose before being defined), one widget (Widget 5 §5) whose readout is essentially descriptive prose rather than a verifiable computation, and a notable mathematical typo in the Widget 6 readout (`c(3) = c(1)^2 - 2 c(2) + 2 c(1)` is presented as a "Hauptmodul defining relation" — it is not).

## Findings
### Notation drift
- _None._ The page uses `\mathbb{M}`, `\mathrm{SL}_2(\mathbb{Z})`, `\mathrm{SL}_2(\mathbb{R})`, `\mathcal{H}`, `\mathcal{H}^*`, `V^{\natural}`, `\mathbb{Z}`, `\Gamma_0(N)`, `\Gamma_0(N)+`, and `q = e^{2\pi i\tau}` consistently with both `vertex-operator-algebras.html` and `modular-forms.html`.
- Minor cosmetic only: target uses `V^{\natural}` (with braces) early (§3) and switches to `V^\natural` (no braces) starting §5; both render identically, but `vertex-operator-algebras.html` uses the unbraced form throughout. Cosmetic, low priority.
- `\tr` macro is used inline (`\tr\!\left(g\,\big|\,V^{\natural}_n\right)`) consistent with the page-level macro defined in the KaTeX loader; matches both peers.

### Undefined jargon
- **"vertex operator algebra (VOA)"** appears at §5 line 653 ("Frenkel, Lepowsky, and Meurman (1988) constructed $V^{\natural}$ as a **vertex operator algebra** (VOA), built as the $\mathbb{Z}/2$-orbifold of the Leech-lattice VOA") inside the prose explanation of Borcherds' proof, three sections before §8 schematically defines a VOA. The cross-link to `vertex-operator-algebras.html` only appears in §8's `<aside class="callback">`. Recommend forward-link the first occurrence (§5) directly to `./vertex-operator-algebras.html` or to `#voa`.
- **"generalized Kac–Moody algebra"** is used in §5 ("It is a *generalized Kac–Moody algebra*: like an ordinary Kac–Moody algebra…") with only an italicized informal gloss; "Kac–Moody" itself has no callback or definition. The hero's prerequisite list mentions Lie groups (`./lie-groups.html`) but not Kac–Moody specifically.
- **"orbifold"** / **"orbifolding"** is used in §5 and §8 without definition; §8 uses it as if defined ("Orbifolding. Given a VOA $V$ with a finite-order automorphism $g$, one can form a new VOA $V/g$"). This is the closest the page gets to a definition, and it occurs after the term has already been load-bearing in §5.
- **"Hall divisor"** appears at §7 line 1001 ("for each Hall divisor $e \| N$ one has an Atkin–Lehner involution $w_e$") without definition. Concrete example or one-line definition would help — e.g. "$e$ a Hall divisor of $N$ (meaning $\gcd(e, N/e) = 1$)".
- **"supersingular"** is used in §7's widget caption ("show $|\mathbb{M}|$ supersingular primes", line 1017) and in §7 prose ("the prime divisors of $|\mathbb{M}|$") well before the term is defined at line 1085 ("Why supersingular? A prime $p$ is **supersingular** in Ogg's sense if…"). The widget label is the first appearance.
- **"replicable"** is used as a noun at §6 line 825 ("called **replicable**") which is fine, but Widget 5's readout (§5) already invokes "Borcherds' replication recursion" before §6 actually defines replicability.
- **"Faber polynomials"** appear in Widget 6's title "Widget 6 · Faber-polynomial recursion for $c(N)$" (in the §6 widget caption); they are then defined a few paragraphs above the widget in §6. Borderline — the widget caption appears before the definition only because the surrounding prose flows top-to-bottom; defensible.
- **"Hauptmodul"** appears in §3's closing paragraph ("genus-zero modular functions for specific subgroups of $\mathrm{SL}_2(\mathbb{R})$") before §4's note formally defines it as "Hauptmodul (generator of the field of meromorphic functions)". The "genus-zero" gloss in §3 partly compensates, but a parenthetical definition at first use would be cleaner.
- **"holomorphic VOA of central charge $24$"** appears at §9 line 1265 with no callback to the central-charge concept — that lives in `vertex-operator-algebras.html#virasoro`. Add a forward-link.

### Tone mismatches
- Hero copy is appropriately conversational and matches the peers' register ("John McKay noticed the line. John Conway and Simon Norton turned it into a conjecture. Richard Borcherds turned it into a theorem and got the Fields medal for it.").
- §5 ("Borcherds' proof — a sketch") is dense but well-narrated; the three-layer scaffolding is the strongest pedagogical move on the page.
- §6 §"Replication formulas and Hauptmodul recursions" briefly devolves into a formula wall around line 817: the "first instance is `c(4) = ½(c(1)^2 + c(2))·2 − c(2)·c(1)/c(1) + …`" is presented as a worked example but the right-hand side is malformed (the `· 2 − c(2)·c(1)/c(1)` simplifies to `c(2) − c(2) = 0`, leaving `c(1)^2`, which does not equal `c(4)`). The "in practice one tabulates the recursion symbolically and verifies on the $j$-coefficients" handwave then walks back the worked instance. This is the largest tone/clarity hit on the page — it reads as both formula-without-narration and as honest-but-frustrated.
- §6 Widget 6 has several `match: null` entries and inline source-comments noting "this instance is degenerate", "the real recursion uses N=2", "we keep the demo honest by just showing the hand-verifiable identity"; these honest disclaimers leak into the readout text and undercut the widget's authority. The reader watching `N=3` see "c(3) = c(1) c(2) - c(1) c(2) (only r=0 term; r out of range) = 0 -- this instance is degenerate" will reasonably conclude the widget is broken.
- §7 ("Genus-zero groups and Ogg's coincidence") strikes the right pedagogical rhythm; the Jack Daniel's anecdote is in keeping with the peers' tone (compare `vertex-operator-algebras.html`'s "the algebraic shadow of two-dimensional conformal field theory").
- §10 ("Where moonshine lives in the notebook") is a good closing — peer pages do not all have this kind of cross-reference summary, and it is a positive deviation.

### Missing worked examples
- **§2 (Monster group).** Widget 2 is a row-highlighter that prints a hint string on click, not a computation. Compare Widget 1 (j-coefficient table — sliders + computed table) and Widget 3 (McKay decomposition calculator — actual BigInt arithmetic). Section 2 has the dimension table and the order of `\mathbb{M}`, but the only "thing to poke" is a click that surfaces a precomputed sentence. Consider a small toy that lets the reader pick `n` and check that some `c_n` equals a specific integer combination of `\dim V_i`.
- **§5 (Borcherds' proof — a sketch).** Widget 5 is the weakest. The recipe for `(m,n)=(2,3)` reads "The coefficient of p^2 q^3 on the LHS, computed from c(mn) for mn ≤ 6, equals c(2)·c(3) + {lower} — see note" — there is no actual computation, just a list of values and a `desc`/`check` string. Promise of a numerical check is unfulfilled. Reverting to a single fully-worked instance (e.g. evaluate one log-expansion coefficient symbolically and compare BigInt sides) would bring this in line with Widget 3's standard.
- **§6 (Replication formulas).** Widget 6 (already noted under Tone) — the source comments admit the recursion isn't actually being verified and the displayed identity for `N=2` is wrong. Section 6 has a worked example only in name.
- **§8 (Vertex operator algebras, schematically).** No widget. This is defensible because the section is intentionally a teaser ("We will not build VOAs here") that defers to `vertex-operator-algebras.html`, but the AGENTS.md house rule is "every numbered `<h2>` has a worked widget." A minimal widget — perhaps locality bookkeeping like `vertex-operator-algebras.html` Widget 1 (mode bookkeeping), copied or linked — would satisfy the convention without lengthening the page much.
- **§9 (Generalized moonshine).** Widget 8 (commuting-pair selector with `S`/`T` actions) is a strong widget for the section, but the `S` and `T` action maps include several "_{not_in_table}" cases that silently fall through (e.g. `applyS("3A,e")` returns `"e,3A_{not_in_table}"`, which is then rejected by `if(PAIRS[next]) cur = next`). Reader sees the readout stay frozen; only the history list updates. Either prune the `not_in_table` cases or surface a "(off-table — pick a base pair below)" message.

### KaTeX macros / formatting
- The page-level KaTeX loader matches the peers exactly (`\Spec`, `\Gal`, `\Hom`, `\tr`, `\ad`, `\ind`); no novel macros. `\tr` is used in `\tr\!\left(g\,\big|\,V^{\natural}_n\right)` consistently.
- `$\!\|\!$` is used as the divisibility "Hall divisor" symbol at §7 line 1001 ("for each Hall divisor $e \| N$"); this renders fine in KaTeX. No issue.
- Widget 8's `<button>` labels use embedded LaTeX (`$S = \\begin{psmallmatrix}0&-1\\\\1&0\\end{psmallmatrix}$`, line 1156) inside button text. KaTeX auto-render rewrites button textContent in place, so this works, but the inline `psmallmatrix` is non-standard relative to the `\big(\begin{smallmatrix}…\end{smallmatrix}\big)` form used elsewhere in the same section (lines 996, 1001, 1132). Cosmetic; suggest standardising on one of the two.
- The `<select>` in Widget 8 (§9) contains LaTeX-flavored option labels like "(2A, 2B)  commuting Fischer × Conway" — these are pure-text, no KaTeX, so the `js/katex-select.js` shim is not strictly required for them, but `js/katex-select.js` is loaded in the `<head>` regardless.
- §7 widget Widget 7 has an escaped `\\mathbb{M}` inside a button label ("show $|\\mathbb{M}|$ supersingular primes", line 1017) — this is correct because the string lives inside a JS template literal context, but it is the same pattern used in Widget 8's button labels (line 1156–1157), so consistent.
- Widget chrome (`.widget`, `.hd`, `.ttl`, `.hint`, `.row`, `.readout`, `.note`, `.ok`, `.bad`, `.pill`) is used correctly throughout. One ad-hoc utility class `.bignum` is defined locally (line 126) for the order of $\mathbb{M}$; this is a reasonable one-off, though a plain `<p style="…">` would be equally clear.
- Top-of-`<body>` helper script block (`$`, `$$`, `SVG`, `ensureArrow`, `drawArrow`, `drawNode`) is verbatim-equivalent to the canonical block in `vertex-operator-algebras.html` (spot-checked lines 187–234). Helper-block hygiene: clean.
- Script-load ordering in `<head>` differs slightly from the canonical layout: target loads `progress.js`, `quiz.js`, `katex-select.js`, `quizzes/bundle.js` immediately after the breadcrumb auto-block but before the `<style>` block (lines 21–24), whereas `vertex-operator-algebras.html` and `category-theory.html` load these after the `<style>` block (lines 176–180). Both work; non-blocking. Cosmetic.
